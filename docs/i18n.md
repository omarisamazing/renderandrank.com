# Multilingual SEO (USA/Europe): i18n rollout guide

Root `/` serves **en-US** (and `x-default`). Every other locale lives under its
prefix subdirectory: `/es/`, `/fr/`, `/de/`, `/it/`, `/pt/`, `/nl/`.

## How it works

- `astro.config.mjs` declares `i18n` (`defaultLocale: 'en'`,
  `routing: { prefixDefaultLocale: false }`) and `site` reads
  `PUBLIC_SITE_URL` (default `https://renderandrank.com`), so staging on
  `*.pages.dev` and shipping on the root domain differ by env var only.
- `src/config/site.ts` owns `localeMeta` (html lang, `og:locale`, hreflang),
  `canonicalUrlFor()` (always root-anchored — staging never mints a
  `pages.dev` canonical), `localizedPath()`, `LOCALIZED_ROUTES`, and
  `STAGING_HOST_SUFFIX`.
- `src/layouts/Layout.astro` renders per-locale `<html lang>`, canonical, the
  hreflang cluster, `og:locale` + alternates, dynamic schema `inLanguage`,
  and a build-time `<meta robots noindex>` whenever the host or canonical is
  `*.pages.dev`.
- `src/i18n/ui.ts` + `src/i18n/utils.ts` (`getLangFromUrl`, `useTranslations`)
  drive all chrome strings. `Navbar`, `Footer`, `HeroSection`, `BookCallButton`,
  and `MobileNav` are locale-aware; `LanguageSwitcher.astro` (dependency-free
  `<details>` dropdown) keeps visitors on the same page across locales.
- `src/components/HomePage.astro` is the shared homepage composition; root
  `src/pages/index.astro` and each `src/pages/{es,fr,de,it,pt,nl}/index.astro`
  wrap it with transcreated title/meta/keywords.

## hreflang rule (strict)

`Layout` emits the **full cluster + `x-default` only for paths listed in
`LOCALIZED_ROUTES`** (currently `['/']`). Every other page emits a
self-referential hreflang until its locale wrappers exist — hreflang must
never point at a 404. When you ship wrappers for a new path, add it to
`LOCALIZED_ROUTES` in the same change.

## Adding locale coverage for a page

1. If the page markup is inline, factor the body into a shared component
   (see `HomePage.astro` pattern).
2. Add `src/pages/{locale}/<path>.astro` per locale with transcreated
   `title`/`description`/`keywords` (transcreate — never machine-translate —
   using the per-locale targets in `docs/keyword-map.md`).
3. Add the unprefixed path to `LOCALIZED_ROUTES` in `src/config/site.ts`.
4. Rebuild and assert: `lang`, canonical, 8-tag cluster, localized H1, sitemap
   entry (see verification commands in `PROGRESS.md` / session notes).

Shipped: `/` (batch 1), `/pricing` + `/services` + 3 detail pages (batch 2 —
hero/meta/chrome localized; matrix, timeline, service-data body copy and
detail H1s stay English until phase 3: `src/data/services.ts` + section
dictionaries per locale).

Suggested order for the rest: `/contact`, `/book-a-call`, `/about`, then
`/blog` (index + posts need per-slug wrappers).

## Staging de-indexing

Two layers (because `public/_headers` matches paths, not hostnames):

1. **Build time** — `Layout.astro` emits `noindex, nofollow` when
   `Astro.url.hostname` or the canonical contains `.pages.dev`. Staging builds
   must set `PUBLIC_SITE_URL=https://<project>.pages.dev`.
2. **Functions runtime** — `functions/_middleware.ts` stamps
   `X-Robots-Tag: noindex, nofollow` on every Functions response served from a
   `*.pages.dev` host (API routes, admin).

Production on the root domain stays indexable with zero code changes.

## OpenSEO workflow (once MCP is authorised)

1. `whoami` → `list_projects` → `create_project renderandrank.com` (if needed).
2. `seo-project-setup`: fill `business_overview` / `current_goal` /
   positioning, competitors, key pages (`update_project_context`).
3. `keyword-research`: seeds in `docs/keyword-map.md`, one call per
   market/language; hydrate striking-distance GSC queries when Search Console
   is connected.
4. `keyword-clustering`: map winners to pages before writing locale copy.
5. `seo-audit` (Lighthouse off): confirm the hreflang/canonical/schema
   surface after each rollout step; log research in the project context.

The OpenSEO MCP endpoint (`https://app.openseo.so/mcp`) is wired in
`.mcp.json` + `opencode.json`. First connection completes OAuth login in the
client; headless/CI uses `Authorization: Bearer oseo_...` (see
https://openseo.so/docs/mcp). Never commit the key.
